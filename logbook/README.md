# 잔상 · 비공개 움직임 기록

[개인 기록함](https://ghosting-logbook.jansang.workers.dev/logs/)은 소유자 비밀번호로 여는 별도 사이트다. 원본 영상·의도·AI 해석·의미 유사도를 함께 돌아본다.

## 자동 보관 흐름

1. 원래 잔상 화면에서 시작하면 개인 기록함 탭을 준비한다. 카메라로 시작한 기록은 소리 없이 자동 녹화한다.
2. 영상과 결과는 원래 화면의 IndexedDB에 먼저 보관한다. 로그인이 안 됐거나 창이 차단돼도 기기 대기 기록으로 남기고 상태를 표시한다.
3. 기록함에 로그인하면 대기 큐가 자동 동기화된다. 별도의 수동 저장 버튼을 눌러야만 온라인에 보관되는 흐름은 아니다.
4. AI 해석 뒤 의도·자유 입력·유사도가 바뀌면 같은 기록 ID의 새 revision으로 메타데이터를 갱신한다. 이미 보관한 영상은 다시 업로드하지 않는다. 기기에 즉시 반영하고 온라인 전송은 약 8초 간격으로 묶는다.
5. 목록에서 영상과 결과를 다시 읽거나 JSON·영상을 내려받고, 필요하면 확인 후 기록을 삭제한다.

**기기 보관과 온라인 저장 완료를 구분한다.** 미로그인 상태의 대기 자료는 소유자 기록함에 아직 올라간 것이 아니다. 브라우저 데이터 삭제·저장 공간 회수·시크릿 세션 종료로 기기 대기 자료가 사라질 수 있다. 영상에는 얼굴과 주변 공간이 포함될 수 있으며 음성은 녹음하지 않는다.

예전 링크로 열어 받은 미리보기에는 수동 저장·재시도 버튼이 남아 있다. 현재 자동 동기화 창은 `?capture=1&save=1&auto=1` 모드로 여러 움직임을 이어서 받는다.

## 점수 읽기

새 기록의 **의미 유사도**는 내 표현과 후보 단어를 실제 fastText 벡터로 비교한 코사인 × 100이다. 범위는 -100~100이며 음수도 그대로 보관한다. 확률·정확도·동작 일치율이 아니다. 모델과 계산 방식도 함께 남긴다.

이전 기록의 **AI 적합도**는 AI가 자체 보고한 0~100 수치다. 의미 유사도와 같은 값으로 바꾸지 않고 원래 표기를 유지한다. 점수가 없으면 0으로 채우지 않는다. MotionGPT를 사용한 기록의 설명·모델·변환 출처는 분석 메타데이터의 `motionCaption`에서 확인한다.

단어 벡터 평균은 어순·부정·문맥을 충분히 구별하지 못하며 제한된 사전에 없는 표현은 측정 불가다. 높은 값이 실제 의도를 정확히 읽었다는 뜻은 아니다.

## 저장과 접근

| 자료 | 보관 위치 |
| --- | --- |
| 동기화 전 영상·입력·분석 대기 큐 | 원래 화면의 브라우저 IndexedDB |
| 온라인 원본 영상 | Cloudflare KV, 소유자 인증 API로만 조회 |
| 의도·분석·유사도·revision | Cloudflare D1 |
| 로그인 세션 | D1의 토큰 해시·만료 시각, Secure·HttpOnly·SameSite=Strict 쿠키 |
| 비밀번호 | 서버의 PBKDF2 해시·salt 비밀 값 |

로그인 세션은 최대 12시간이다. 만료되면 로그 화면의 자료를 숨기고 원래 화면에 정확한 기록 ID·revision으로 오류를 알려준다. 원래 화면의 대기 기록은 로그인 후 다시 보낼 수 있다.

영상당 15MiB, 영상 전체 500MiB, 기록 500개가 앱의 한도다. 온라인 쓰기 요청 제한은 분당 10회이며 지연·제한 시 원래 화면의 기기 대기 큐를 유지한다. Cloudflare 서비스 할당량은 별도로 적용된다. KV 지역 간 반영이 늦으면 잠시 후 영상을 다시 연다.

Gemini와 로컬 MotionGPT는 이 저장소의 원본 영상을 받지 않는다. 의미 유사도 계산도 브라우저에서 처리한다. 개인 기록함에 로그인한 뒤에는 의도와 유사도 결과가 비공개 저장소에 함께 보관된다.

## 갱신 API와 동시성

- `POST /api/records`: 최초 JSON 메타데이터 + 선택적으로 존재하는 원본 영상의 multipart 업로드.
- `PUT /api/records/:id`: 기존 영상은 유지하고 JSON 메타데이터만 갱신.
- 동일하거나 낮은 revision은 멱등 처리한다. 최신 revision을 비교·교환 방식의 SQL로 보존한다.
- 기록 ID·촬영 시각·입력 방식은 바꾸지 못한다. 삭제 후 같은 ID로 다시 만든 영상 세대도 이전 요청이 덮어쓰지 못한다.
- 연속 창은 받은 새 revision을 직렬 처리한다. 인증된 실제 opener와 허용 출처만 받아 저장·수신·실패 메시지에 ID와 revision을 함께 돌려준다.

기존 D1에 `revision` 열이 없는 경우 배포 전에 한 번만 추가한다. 새 설치는 `schema.sql`을 사용한다.

```powershell
npx wrangler d1 execute ghosting-logbook --config logbook/wrangler.toml --remote --command "ALTER TABLE records ADD COLUMN revision INTEGER NOT NULL DEFAULT 0;"
npx wrangler deploy --config logbook/wrangler.toml
```

소유자 비밀번호는 작업 환경의 `.codex-preview/logbook-owner-access.txt`에서 관리한다. 이 파일·실제 키·세션 값·원본 영상·모델 가중치를 Git이나 제출 ZIP에 넣지 않는다. 배포 설정은 이미 연결한 Cloudflare 계정을 전제로 하며 다른 계정에 새로 설치할 때는 저장소와 인증 비밀 값을 별도로 준비한다.

검증 명령은 프로젝트 루트에서 `node --test tests/logbook*.test.cjs`다. 자동 테스트는 인증·동시성·저장 계약을 확인하며 실제 춤 영상의 녹화 품질 평가와는 다르다.
