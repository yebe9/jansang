# 잔상 — 움직임을 남기는 방법

> 몸의 모양 없이, 움직임의 궤적과 속도만으로 춤의 느낌을 전달할 수 있을까?

전기정보공학과 춤, 컴퓨터 그래픽에 대한 관심에서 출발한 WebGL WIP 프로토타입입니다. 마우스 또는 터치로 짧은 움직임을 만들고, 입력한 시간에 맞춰 재생합니다. 실제 춤의 동작 인식이나 감정 분류를 수행하지 않습니다.

## 실행

`dist/index.html`을 Chrome 또는 Edge에서 열면 됩니다. 빌드, 설치, 외부 라이브러리, API 키가 필요하지 않습니다. WebGL이 가능한 브라우저가 필요합니다.

로컬 서버를 사용하려면 이 폴더에서:

```sh
node server.cjs
```

표시된 `http://127.0.0.1:4173`에 접속하세요.

## GitHub Pages

- 저장소: https://github.com/yebe9/jansang
- 체험 주소: https://yebe9.github.io/jansang/

- 저장소의 Settings → Pages → Source는 GitHub Actions를 사용합니다. 외부 라이브러리나 빌드 단계가 필요하지 않습니다.

## 핵심 경험

1. 예시를 재생하거나 **기록하기**를 누릅니다.
2. 무대에서 누른 채 움직이면 최대 10초 동안 기록합니다. 손을 떼면 선이 끊어지고 다시 누르면 새 선을 그립니다. **기록 마치기**로 일찍 끝낼 수 있습니다.
3. **재생**으로 원래 타이밍을 확인합니다. 일시정지, 구간 탐색, 0.5/1/1.5배속 재생을 지원합니다.
4. **속도에 따라 / 한 가지 색**을 전환해 같은 움직임의 인상을 비교합니다.
5. 인상을 선택하거나 화살표 버튼으로 WebGL 화면을 PNG로 저장합니다. 격자와 UI는 PNG에 포함되지 않습니다.

`R`: 기록 준비/취소/종료 · `Space`: 재생/일시정지 · `Esc`: 기록 종료 또는 재생 일시정지. 입력 요소에 포커스가 있으면 해당 요소의 기본 키보드 동작을 유지합니다.

움직임과 감상 선택은 메모리에만 있습니다. 서버로 보내지 않으며 새로고침하면 사라집니다. 새 기록은 실제로 무대를 누를 때 이전 움직임을 교체합니다. 준비 상태에서 취소하면 기존 움직임이 보존됩니다.

## 질문과 조사

- 출발점: 춤을 볼 때 형태뿐 아니라 속도, 멈춤, 방향 전환이 인상을 만드는가?
- 구현 가설: 좌표와 시간만 남겨도 움직임의 리듬을 일부 전달할 수 있다.
- 비교 조건: 동일한 궤적과 타이밍을 유지한 채 속도별 색상과 단색을 비교한다.
- 아직 하지 않은 조사: 실제 관객 대상 사용성 테스트, 무용 동작과 마우스 궤적의 비교, 선행 사례 조사. 아래 질문은 앞으로 확인할 내용이며 검증된 결과가 아니다.
- 관객에게 물을 것: 어떤 부분이 춤처럼 느껴지는가? 색을 바꾸면 같은 움직임의 인상이 달라지는가? 무게와 관절 정보가 없을 때 무엇이 사라지는가?

## 핵심 구조

`dist/index.html`: 화면과 의미 있는 UI 구조

`dist/styles.css`: 반응형 레이아웃, 무대 격자와 컨트롤

`dist/app.js`: 입력 기록, 상태 전환, 속도 계산, WebGL 셰이더, 재생

```text
Pointer Events
  → 정규화한 좌표 (x, y), 경과 시간 t, stroke 번호 저장
  → 거리 / 시간 차이로 속도 계산 + 간단한 평활화
  → 속도를 색에 대응
  → 각 선분을 삼각형 2개로 구성
  → 넓고 흐린 선 + 좁고 밝은 선을 가산 합성
  → 저장 시간에 맞춰 재생할 점을 선택하고 마지막 선분 보간
```

외부 그래픽 라이브러리 없이 WebGL 1.0을 직접 사용합니다. 3D 신체를 복원하지 않으며 입력은 2D입니다. 속도는 화면 높이/초 기준으로 계산합니다. 창 크기가 바뀌면 정규화된 궤적을 현재 무대에 맞춰 표시하므로 형태의 비율은 달라질 수 있습니다.

## AI USE NOTE

- 사용자: 전기정보공학, 춤, OpenGL, 산책이라는 관심사를 제안하고 WebGL 구현 및 프로토타입 제작을 선택했다.
- AI: 질문과 MVP 범위를 제안하고 HTML/CSS/JavaScript 및 WebGL 렌더러와 문서 초안을 작성했다.
- 범위 결정: 실제 웹캠 동작 인식 대신 마우스 입력, 서버 없이 로컬 상태, 한 가지 핵심 경험을 구현한다.
- 발표 전 직접 확인할 부분: 좌표 정규화, 속도 계산, 셰이더 속성, 상태 전환, 시간 기반 재생의 작동 방식.
- AI 결과를 무비판적으로 검증했다고 주장하지 않는다. 사용자는 직접 체험한 뒤 본인의 수정과 판단 과정을 이 문서에 추가해야 한다.

## 한계와 앞으로 배울 점

- 마우스는 몸의 무게, 관절, 공간 이동을 담지 못한다. 이것이 작품 질문의 중요한 한계다.
- 속도와 색의 대응은 임의의 디자인 선택이다. 특정 감정을 객관적으로 판단하지 않는다.
- 합성된 시작 예시는 실제 사용자 기록과 구분해 표시한다.
- 터치 장치와 마우스는 입력 방식이 달라 같은 조건이라고 볼 수 없다.
- 관객의 선택을 모으거나 여러 기록을 비교 저장하는 기능은 아직 없다.
- 실제 제작 중의 실패와 사용자 관찰은 직접 경험한 뒤 추가할 것. 없는 실험 결과는 기재하지 않는다.

## 3분 발표 초안

- 0:00–0:30 질문: 몸의 형태 없이도 춤의 느낌이 전달될까? 전공과 춤에 대한 관심을 연결했다.
- 0:30–0:50 탐색: 좌표·속도·멈춤 중 무엇을 남길지 고민했다. 현재는 좌표와 시간으로 범위를 줄였다.
- 0:50–1:40 시연: 직접 기록 → 재생 → 속도별 색과 단색 비교.
- 1:40–2:30 과정: AI와 함께 WebGL로 구현했다. 점의 기록과 삼각형 렌더링 구조를 설명한다. 마우스 입력의 한계도 설명한다.
- 2:30–3:00 피드백: 무엇이 춤처럼 느껴졌는가? 몸의 정보를 하나 더한다면 어떤 것이 좋을까?
