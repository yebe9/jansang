# Ghosting — 움직임을 남기는 방법

전유빈 · WebGL 기반 인터랙티브 웹 · WIP 프로토타입

[작업물 체험](https://yebe9.github.io/jansang/) · [GitHub 소스 코드](https://github.com/yebe9/jansang)

## 질문 한 문장

> 내가 움직임에 담은 느낌과, 몸의 외형 대신 궤적과 속도를 읽은 AI의 해석은 어떻게 다를까?

## 현재 상태

웹캠으로 최대 10초의 움직임을 남긴 뒤, 어두운 큰 결과 팝업에서 내 의도와 AI의 인상을 비교한다. **손끝으로 그리기**는 최대 양손을 동시에 추적한다. 손마다 21개, 총 최대 42개 지점 중 선택한 검지 끝 또는 손목을 손별 자취로 그린다. **몸으로 남기기**는 얼굴을 제외한 전신 22개 지점을 기록하고 양 손목·양 발목·골반 중심의 다섯 자취를 그린다.

해석 결과는 실제 Gemini 응답을 받은 경우에만 표시한다. 사용자가 제공한 [춤 표현 50선](./dance_descriptions.txt)의 여섯 범주를 바탕으로 대표 표현과 인상 단어를 고르고, 짧은 감상과 펼쳐 볼 수 있는 근거를 생성한다. 연결 실패나 시간 초과 시에는 오류와 재시도 안내를 표시하며 규칙 기반 감상으로 대체하지 않는다.

내 느낌은 **5글자 이내의 짧은 표현**으로 적는다. 긴 입력은 선택 항목인 상세 설명에 원문 전체를 보존한다. 결과에서는 내 의도와 AI가 고른 인상 단어·감상을 나란히 읽고 차이를 살펴본다.

공개 페이지의 AI 요청은 [Cloudflare Worker](https://jansang-motion-api.jansang.workers.dev)를 통해 Gemini로 전달한다. Worker 배포와 서버 비밀 값 등록을 마쳤고 공개 API 상태 확인도 통과했다. 방문자가 API 키를 입력하는 방식은 아니다. [로컬 서버](http://127.0.0.1:4173/)에서는 공개 주소 설정과 관계없이 같은 컴퓨터의 API를 우선 사용한다. 연결 구조와 관리 방법은 [AI연결안내.md](./AI연결안내.md)에 있다.

공개 API에 10초 길이의 **합성 양손 좌표**를 보내 HTTP 200 응답을 **약 17초(16.987초)**에 받았다. `gemini-3.5-flash-lite`는 “유연한 · 유려한 · 매끄러운”을 반환했다. 한 번의 합성 자료 측정으로, 모든 요청의 응답 시간이나 실제 양손 추적 품질을 보장하지 않는다. 이전 로컬 측정에서는 2.18초 응답과 분석 팝업·의도 비교 화면을 확인했다.

## 질문과 조사

전기정보공학과 춤, 컴퓨터 그래픽에 대한 관심에서 시작했다. 처음 질문은 “몸의 모양 없이 움직임의 궤적과 속도만으로 춤의 느낌을 전달할 수 있을까?”였다. 마우스 궤적으로 시작한 뒤 웹캠의 양손과 전신으로 입력을 넓혔다. 의도와 해석의 차이를 살펴보기 위해 결과 비교 화면을 추가했다.

- **MediaPipe Hand Landmarker:** 손마다 21개 지점을 반환하며 `numHands: 2`로 양손을 받는다. 손 모델은 얼굴 좌표를 반환하지 않는다. [공식 손 모델](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker) · [웹 가이드](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js)
- **MediaPipe Pose Landmarker Full:** 내부적으로 33개 포즈 좌표를 추정하지만 얼굴에 해당하는 0–10번은 반환 직후 버리고 몸·손·발의 22개 좌표만 사용한다. 추론은 최대 초당 15회로 제한했다. [공식 자세 모델](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker)
- **Gemini API:** 기본 모델은 `gemini-3.5-flash-lite`이며 `minimal` 추론 설정을 사용한다. 무료 사용 구간이 있지만 할당량과 이용 조건이 적용된다. 낮은 지연을 목표로 한 모델을 골랐으며, 특정 시간 안의 응답 성공을 보장하지 않는다. [모델 안내](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite) · [추론 설정](https://ai.google.dev/gemini-api/docs/thinking) · [요금표](https://ai.google.dev/gemini-api/docs/pricing)
- **춤의 표현어:** 제공된 50개 표현을 결과 어휘로 사용한다. 별도의 학습된 감정 분류기나 정식 Laban 분류기를 설치한 것은 아니다. 관측한 움직임의 특징을 AI가 표현어와 감상으로 설명한다.

이 프로젝트는 기술 문서와 구현을 통한 탐색이다. 감정 분류의 정확도 평가나 관객 대상 실험은 아직 진행하지 않았다.

## MVP 체험 방법

1. WebGL을 지원하는 Chrome 또는 Edge에서 [공개 페이지](https://yebe9.github.io/jansang/) 또는 로컬 페이지를 열고 **손끝으로 그리기 / 몸으로 남기기**를 고른다.
2. 손 입력에서는 카메라를 준비하고 **검지 끝 / 손목**을 선택한다. 한 손 또는 양손을 보여준 뒤 **10초 기록 시작**을 누른다. 두 손은 별도 자취를 남긴다. 한 손을 놓치면 다른 손은 계속 기록하고, 두 손을 모두 놓치면 기록 시간이 멈춘다. 다시 나타난 손은 새 자취로 이어진다.
3. 전신 입력에서는 어깨·골반·양 발목이 함께 보이도록 물러선 뒤 기록을 시작한다. 양 손목·양 발목·골반 중심의 자취가 남는다.
4. **일시정지**로 멈추거나 오른쪽 메뉴에서 속도별 색의 범례를 확인하고 굵기를 조절한다. 메뉴를 열면 기록도 멈춘다.
5. **결과 보기** 또는 10초 자동 종료로 결과 팝업을 연다. 내 느낌을 5글자 이내로 적고 필요하면 상세 설명을 덧붙인다. 한글 조합이 끝난 뒤 길이를 검사하며, 긴 입력의 원문은 상세 설명으로 옮긴다.
6. **AI로 움직임 해석하기**를 누른다. 자동 해석을 선택했다면 기록 후 요청한다. 대기 중에는 어두운 분석 팝업이 표시된다. 서버 요청 제한은 19초, 브라우저 요청 대기 제한은 20초이며, 제한을 넘으면 오류와 재시도 안내를 표시한다. 이는 성공 응답 시간의 보장이 아니다.
7. 실제 AI 표현과 내 느낌을 비교한다. **어떤 움직임에서 그렇게 느꼈을까요?**를 펼치면 근거를 볼 수 있다. 자취를 재생하거나 구간·배속을 바꾸고 PNG 이미지로 저장할 수 있다.

카메라가 어렵다면 **예시 먼저 보기**로 합성 궤적의 화면 흐름을 체험한다. 예시도 AI 해석에는 서버 연결이 필요하며 실제 사람의 기록으로 표시하지 않는다.

카메라 자동 선택은 물리 카메라를 우선한다. 영상 시작·장치 찾기 실패 시 아직 시도하지 않은 물리 카메라를 최대 두 대 더 시도한다. 실패해도 확인된 **사용할 카메라** 목록에서 직접 선택한 뒤 **카메라 다시 연결**을 누를 수 있다. 사용자가 고른 장치를 임의로 바꾸거나 권한 거부 후 자동 재시도하지 않는다.

## 기록과 분석의 범위

웹캠 영상은 브라우저 안의 MediaPipe 입력으로만 사용한다. 소리를 수집하지 않으며 원본 영상을 녹화·저장·전송하지 않는다. 라이브러리와 모델 다운로드에 인터넷이 필요하고 카메라는 HTTPS 또는 로컬 서버에서 사용한다.

손 입력은 최대 42개 손 좌표, 전신 입력은 얼굴을 제외한 22개 몸 좌표를 사용한다. 전신 모델 내부에는 얼굴을 포함한 포즈 추정 과정이 있지만 앱은 얼굴 좌표를 표시·기록·분석·전송하지 않는다. 카메라 미리보기 자체의 얼굴을 가리는 기능은 아니다.

메모리에는 2D 좌표, 시간, 기록 구간과 자취만 남긴다. 새 기록이나 새로고침으로 이전 내용이 사라지며 결과 화면으로 이동하면 카메라를 종료한다. 손의 임시 식별자는 자취 분리용으로 실제 왼손·오른손이나 사람의 신원을 보장하지 않는다.

AI 해석을 요청할 때 브라우저는 최대 60개 시점의 관측 좌표와 속도·멈춤·범위·방향 변화 등의 수치를 서버에 보낸다. 서버는 기록 경계를 우선해 최대 24개 실제 시점을 고르고, 손은 손목·검지 뿌리·다섯 손끝의 7개 지점을 손마다, 전신은 22개 지점을 Gemini에 전달한다. 같은 시점의 양손은 함께 유지하고 좌표는 소수 셋째 자리까지 정리한다. 손은 실제로 관측한 것만 구분하며 보이지 않는 손을 채워 넣지 않는다. 입력 종류도 전달해 손 자료로 전신을 관측했다고 설명하지 않도록 한다. **얼굴 좌표·이미지, 원본 영상, 음성, 짧은 의도와 상세 설명은 Google에 보내지 않는다.** 서버 코드에는 움직임을 파일이나 데이터베이스에 저장하는 기능이 없다. 외부 API에는 제공자의 데이터 처리 조건이 적용된다.

## 핵심 구조

```text
웹캠 ┬─ Hand Landmarker → 양손 최대 42개 좌표 → 손별 자취
     └─ Pose Landmarker Full → 얼굴 제외 22개 좌표 → 다섯 자취
                            ↓
               관측 좌표와 움직임 수치 계산
                            ↓ AI 요청
        비공개 키를 가진 서버 → Gemini 3.5 Flash-Lite
                            ↓
           제공된 50개 표현 중 인상 + 감상과 근거
                            ↓
               내 의도와 AI의 감상을 나란히 비교
```

- `dist/app.js`: 기록 상태, WebGL, 재생, 비교 화면, AI 요청과 대기 팝업.
- `dist/pose-camera.js`: 모드별 MediaPipe, 손 추적 분리, 장치 선택과 해제.
- `dist/motion-analysis.js`: 좌표 정리, 움직임 수치, 최대 60개 시점 샘플링.
- `dance_descriptions.txt`, `api/dance-vocabulary.mjs`: 제공된 표현 원문과 AI 출력의 허용 어휘.
- `server.cjs`, `api/handler.mjs`: 로컬 서버와 Gemini 호출·출력 검증.
- `api/worker.mjs`, `wrangler.toml`: 공개 Cloudflare Worker와 모델·허용 출처 설정.
- `dist/config.js`: 공개 API 주소만 보관하며 비밀 키는 넣지 않는다.

WebGL 1.0으로 넓고 흐린 선과 좁고 밝은 선을 합성한다. 수치 분석은 서로 다른 손·획·기록 구간을 연결하지 않으며 250ms 이상 관측이 끊긴 구간도 건너뛴다. 전신은 각 구간에서 상체·하체·몸통 중 가장 활발한 영역의 속도와 이동을 반영한다. 최소 1초, 유효 관측 8개, 연속 관측 합계 500ms를 충족해야 AI 요청을 허용한다.

## AI 활용 과정 · AI USE NOTE

- 발표자가 전기정보공학·춤·OpenGL·산책에 대한 관심을 제시하고, AI와 WebGL 움직임 기록으로 범위를 좁혔다.
- AI가 코드·문서 초안을 작성했고 발표자는 시작 팝업, 전체 무대, 옆 설정 메뉴와 어두운 큰 결과 팝업을 선택했다.
- 마우스 입력에서 양손과 전신으로 확장했다. 영상 추적과 생성형 해석을 분리하고 원본 영상 대신 좌표를 전달하기로 했다.
- 제공한 춤 표현 50선을 AI 결과 어휘로 적용했다. 실제 API 응답만 해석으로 표시하고 규칙 기반 대체 감상은 제거했다.
- 긴 대기를 줄이기 위해 모델과 추론 설정을 바꾸고 요청 제한을 추가했다. 의도 입력을 짧은 표현과 상세 설명으로 나누었다.
- AI 출력의 사소한 공백·코드펜스·중복은 정리하되 모델이 실제로 쓴 허용 표현 1–3개만 사용한다. 일시적인 서버·네트워크 오류는 전체 19초 제한 안에서 한 번만 재시도한다.
- 이전 버전에서 실제 한 손 10초 기록의 의도 “차분한”과 AI의 “머뭇거리는 · 조심스러운 · 섬세한”을 비교하는 화면을 확인했다. 이는 이전 모델·어휘의 결과이며 새 모델의 응답 속도나 현재 50개 어휘의 검증 결과로 보지 않는다.
- 새 모델에는 로컬 API로 10초 길이의 합성 양손 좌표를 보내 2.18초 만에 실제 응답과 허용 어휘 세 개를 받았다. 표현 목록을 지켜도 감상의 세부 내용은 틀릴 수 있으므로 출력 단어 검증과 움직임 해석의 적절성은 따로 확인해야 한다.
- 자동 테스트 **133개**를 통과했다. 양손·전신 기록, 허용 표현과 출력 형식 정리, 제한된 재시도, 서버 19초·화면 20초 종료, 의도 입력 보존, 유사도 기능 제거와 로컬·공개 API 선택 등을 확인했다. 모의 응답을 포함한 테스트이며 실제 춤의 추적 품질 평가와는 다르다.
- 브라우저에서 무료 API 할당량 초과 오류(429)가 표시된 경우도 확인했다. 성공 응답과 별도로 사용량 제한이 체험을 중단할 수 있음을 확인한 사례다.
- 양손 모델과 LGE Camera 연결은 확인했지만 당시 손이 화면에 없어 실제 양손 기록부터 AI 결과까지의 사용 품질은 검증하지 못했다. 전신 춤의 추적 품질과 관객 경험도 추가 확인이 필요하다.

## 실패와 배운 점

**기록의 연결이 가짜 움직임을 만들었다.** 일시정지나 추적 손실 후 위치를 바로 연결하면 실제로 하지 않은 빠른 이동이 생겼다. 손별 자취와 기록 구간을 나눠 해결했다.

**모델 응답을 오래 기다리는 경험이 불편했다.** 경량 모델과 낮은 추론 설정을 사용하며 서버 19초·화면 20초 안에 요청을 끝내도록 했다. 시간 제한은 오류를 알려주는 장치이며 응답 성공을 보장하지 않는다.

**공개 서버의 실행 위치도 API 호출에 영향을 줬다.** 공개 요청에서 `PROVIDER_REGION` 오류가 났다. Worker를 `aws:us-east-1`에 가까운 위치에서 실행하도록 설정한 뒤 같은 합성 양손 자료에서 약 17초 만에 응답을 받았다. [Cloudflare Placement 안내](https://developers.cloudflare.com/workers/configuration/placement/)

**영상 연결과 올바른 카메라는 달랐다.** 가상 카메라의 X 화면도 정상 스트림처럼 열렸다. 물리 카메라 우선 선택과 실패 상태의 장치 목록을 추가했다.

**인상을 수치로 비교하면 정확도로 오해하기 쉽다.** 표현 유사도 기능을 제거하고 의도와 AI의 단어·감상을 직접 비교하도록 정리했다. 작품의 목적은 의도를 맞힌 점수보다 서로 다르게 읽힌 지점을 살펴보는 것이다.

## 한계와 다음 계획

- 겹친 손, 빠른 움직임, 어두운 환경에서는 추적이 흔들릴 수 있다. 임시 ID가 가림 후에도 같은 실제 손을 계속 따른다고 보장하지 않는다.
- 2D 좌표는 힘, 깊이, 음악, 실제 무게중심을 충분히 담지 못한다. 골반 중심은 골반 좌표의 중간점이다. 표현 50선에 음악·힘을 떠올리는 말이 있어도 해당 요소를 실제로 측정한 것은 아니다.
- AI는 줄어든 관측 자료로 감상을 생성하므로 부정확할 수 있다. 검증 중에는 떨어진 합성 손의 움직임을 교차로 묘사하는 경우도 있었다. 허용된 50개 표현을 쓰는 것만으로 근거의 정확성이 보장되지는 않는다.
- 현재는 움직임을 만든 뒤 의도를 적는다. 다음에는 의도를 먼저 기록하고 관객에게 숨긴 채 감상을 받은 뒤 비교하려 한다.
- 여러 기록 저장과 관객 피드백 수집은 아직 구현하지 않았다. API 실패 시 기록과 재생은 유지하지만 해석은 생성하지 않는다.

## 제출물과 실행

[발표자료.md](./발표자료.md)는 작업물 화면 링크를 활용하는 3분 발표 순서이며, [캡션카드.md](./캡션카드.md)는 피그잼에 옮길 내용이다.

제출 ZIP에는 네 Markdown 문서, `dance_descriptions.txt`, `.env.example`, `server.cjs`, `wrangler.toml`, `api/`와 `dist/`를 넣는다. AI 출력 어휘를 정의한 `api/dance-vocabulary.mjs`도 포함한다.

압축을 푼 뒤 Node.js 20.6 이상에서 `node server.cjs`를 실행하면 카메라·자취·재생을 사용할 수 있다. 로컬 AI에는 `.env`에 키를 설정하고 `node --env-file=.env server.cjs`로 실행한다. 공개 API 주소가 설정되어 있어도 로컬에서는 같은 컴퓨터의 서버를 사용하므로 로컬 키가 필요하다. 공개 페이지 방문자는 별도 키 입력 없이 Worker에 연결한다. 자세한 절차는 [AI연결안내.md](./AI연결안내.md)를 따른다. 오프라인에서는 `dist/index.html`의 합성 궤적과 재생만 체험할 수 있다.

**실제 키가 든 `.env`, 비밀 설정, `.git`, 개발 캐시와 미리보기 이미지는 제출하거나 공개하지 않는다.** Gemini API 키는 Cloudflare Worker의 비밀 값에 저장하고 브라우저 코드에는 서버 주소만 둔다. `main`에 push하면 검사 후 `dist`가 Pages에 배포되며, Worker 코드 변경은 별도로 배포한다.
