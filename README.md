## 질문 한 문장

> 몸의 모양 없이, 움직임의 궤적과 속도만으로 춤의 느낌을 전달할 수 있을까?

## 질문과 조사

전기정보공학과 춤, 컴퓨터 그래픽에 대한 관심을 연결한 프로젝트다. 춤에서 몸의 형태를 제외하고 속도, 멈춤, 방향 전환만 남겼을 때에도 움직임의 인상을 전달할 수 있는지 탐색한다.

일주일 MVP 범위에서는 실제 춤을 촬영하거나 인식하는 대신, 마우스나 손가락으로 만드는 짧은 움직임을 사용한다. 좌표와 시간만으로 리듬을 일부 표현할 수 있다는 가설을 세우고, 동일한 기록을 속도별 색상과 단색으로 바꿔 보는 비교 기능을 구현했다.

현재 탐색은 구현과 브라우저 동작 확인 단계까지다. 선행 사례 조사, 실제 관객 대상 사용성 테스트, 실제 무용 동작과 마우스 궤적의 비교는 아직 진행하지 않았다. 결과 화면에는 표현하려던 느낌을 남기고 AI 해석 예시와 나란히 보는 비교 화면을 추가했다. 실제 AI 분석이나 검증된 감정 분류는 구현하지 않았다.

확인하고 싶은 내용은 다음과 같다.

- 어떤 속도 변화나 방향 전환이 춤처럼 느껴지는가?
- 같은 움직임도 색상 표현을 바꾸면 인상이 달라지는가?
- 내가 의도한 느낌과 AI가 읽은 느낌이 다르다면, 그 차이에서 무엇을 발견할 수 있을까?
- 몸의 무게와 관절 정보가 빠지면 무엇이 사라지는가?

## MVP 체험 방법

설치 없이 **[공개 체험 페이지](https://yebe9.github.io/jansang/)**에서 실행할 수 있다. WebGL을 지원하는 Chrome 또는 Edge 사용을 권장한다.

1. 전체 화면 무대 위에 뜨는 **시작하시겠습니까?** 팝업에서 **시작하기**를 누른다. **예시 먼저 보기**를 선택하면 합성 예시의 결과 화면으로 이동한다.
2. 무대 위에서 마우스나 손가락을 누른 채 움직인다. 처음 누르는 순간부터 최대 10초 동안 기록한다. 손을 떼었다가 다시 누르면 별도의 획이 된다.
3. 하단의 **일시정지**로 기록과 시간을 멈춘다. **이어 그리기**를 누른 뒤 무대를 다시 누르면 남은 시간 동안 기록한다. 일시정지 구간은 기록 시간과 재생에서 제외한다.
4. 오른쪽 **색·굵기** 버튼을 누르면 설정 메뉴가 열린다. 속도별 색/단색, 궤적 굵기, 공간 가이드를 조절한다. 기록 중 메뉴를 열면 자동 일시정지하며, 닫은 뒤 **이어 그리기**로 재개한다.
5. **결과 보기**를 누르거나 기록 시간이 10초가 되면 어두운 대형 결과 팝업이 열린다. 왼쪽에서 기록을 재생하고, 오른쪽에서 **내가 의도한 느낌**을 선택하거나 나만의 말로 적는다. 좁은 화면에서는 위아래로 배치된다.
6. **AI 해석 예시 보기**를 펼치면 내 의도와 고정된 해석 예시가 나란히 나타난다. 현재 궤적을 분석한 결과가 아닌 화면 구성 예시다. 속도별 색과 단색도 비교해본다.
7. **잔상 이미지 저장**으로 PNG를 저장하거나 **새로운 움직임 만들기**로 다시 시작한다.

재생 일시정지, 구간 탐색, 0.5/1/1.5배속, 궤적 굵기 조절, 공간 가이드 표시도 지원한다. PNG에는 WebGL로 그린 잔상만 포함되고 격자와 조작 화면은 포함되지 않는다.

결과 팝업의 **잔상 크게 보기** 또는 `Esc`를 누르면 팝업을 닫고 무대 전체로 잔상을 볼 수 있다. **의도와 해석 다시 보기**로 팝업을 다시 열어도 궤적과 의도 입력은 유지된다. 재생 중 팝업을 닫으면 재생을 일시정지한다. 시작, 기록, 결과 모두 짙은 청록색 배경을 사용한다.

키보드 단축키는 그리기 화면에서 `Space`(기록 일시정지·이어서 그릴 준비), `Esc`(설정 닫기 또는 기록 일시정지), 결과 화면에서 `Space`(재생·일시정지), 시작/결과 화면에서 `R`(시작 팝업 열기)다. 팝업은 `Esc`로 닫을 수 있다. 버튼이나 입력 요소에 포커스가 있을 때는 해당 요소의 기본 키보드 동작을 유지한다.

움직임과 의도 선택·입력은 브라우저 메모리에만 보관한다. 기록 데이터를 서버에 전송하지 않으며 새로고침하면 사라진다. 시작 팝업에서 **시작하기** 또는 **예시 먼저 보기**를 누르면 이전 기록과 의도 입력을 지우고 비교 예시를 접는다. 팝업을 닫기만 하면 이전 결과가 보존된다. 다른 탭으로 이동하면 진행 중인 기록이나 재생은 자동 일시정지한다.

## 움직이는 잔상 아이콘

브랜드 아이콘은 하나의 곡선에 옅은 그림자 두 겹과 움직이는 빛을 겹쳐 잔상을 표현한다. 시작 팝업은 한 줄의 곡선에 옅은 그림자와 작은 살구색 빛의 자취만 남겼다. 빛이 곡선을 따라 흐르다가 서서히 사라지는 동작을 반복한다. SVG와 CSS로 구현했으며, 기기의 동작 줄이기 설정에서는 정지된 형태로 표시한다.

## 의도와 AI 해석 비교 — 화면 프로토타입

결과 화면에서 내가 표현하려던 느낌을 선택하거나 80자 이내로 적으면 **나의 의도** 카드에 반영된다. **AI의 해석** 카드는 기본적으로 **연결 대기**로 표시된다. API 키가 없는 현재 단계에서는 서버나 모델을 연결하지 않았다.

**AI 해석 예시 보기**는 항상 같은 단어인 **망설이는**과 같은 해석 문장을 보여준다. 이 예시는 실제 기록, 색상, 의도 입력에 따라 생성되지 않는다. 선택한 단어가 예시와 같은지 다른지만 표시하며, 직접 쓴 문장의 의미를 판정하거나 감정 정확도를 계산하지 않는다. 합성 궤적 예시와 AI 해석 문장 예시는 서로 독립된 데모다.

이 화면의 목적은 ‘내 의도와 다른 해석을 나란히 보았을 때 어떤 질문이 생기는가’를 살펴보는 것이다. 현재는 움직임을 만든 **후에** 의도를 입력한다. 이후 실제 AI를 연결한다면 의도를 AI에 전달하지 않고 궤적만 해석하게 하고, 그리기 전에 의도를 기록하는 방식도 검토할 계획이다.

## 핵심 구조

외부 그래픽 라이브러리 없이 HTML, CSS, JavaScript와 WebGL 1.0을 사용했다. 입력은 2D이며 3D 신체를 복원하지 않는다.

```text
마우스·터치 입력
  → 정규화한 좌표 (x, y), 경과 시간, 획 번호 저장
  → 거리 / 시간 차이로 속도 계산 및 평활화
  → 속도를 색에 대응
  → 선분마다 삼각형 2개 생성
  → 넓고 흐린 선과 좁고 밝은 선을 합성해 잔상 표현
  → 저장된 시간에 맞춰 궤적 재생
```

- `dist/index.html`: 체험 화면과 조작 요소
- `dist/styles.css`: 반응형 레이아웃과 시각 디자인
- `dist/app.js`: 입력 기록, 상태 전환, 속도 계산, WebGL 셰이더, 재생, 의도와 고정 예시 비교

속도는 화면 높이/초 기준으로 계산한다. 결과 화면에서는 기록 시작 당시 무대의 가로세로 비율을 보존해 궤적을 표시한다. 기록 도중 창 크기를 바꾸면 입력 조건이 달라지므로, 같은 크기의 창에서 한 번의 기록을 마치는 것이 좋다.

화면은 **시작 → 기록 → 결과 팝업**으로 나누고, 기록과 재생의 일시정지 상태를 별도로 관리한다. 결과 팝업은 HTML `dialog`를 사용한다. 같은 WebGL 캔버스를 팝업 안팎으로 옮겨 기록을 보존하며, 크기가 바뀌면 다시 렌더링한다. 기록 시간은 활성 구간만 누적한다. 멈췄다가 다시 그리면 새로운 획 번호를 부여해 두 구간 사이에 불필요한 연결선이 생기지 않게 했다.

## AI 활용 과정 · AI USE NOTE

- **주제 선택:** 전기정보공학, 춤, OpenGL, 산책이라는 관심사를 AI와 공유했고, 제안된 방향 중 움직임의 잔상을 선택했다. 구현 환경은 WebGL로 결정했다.
- **구현 범위:** AI와 함께 실제 신체 추적 대신 마우스·터치 입력을 사용하고, 서버 저장 없이 기록과 재생이라는 핵심 경험에 집중했다.
- **AI 작성 범위:** AI가 HTML/CSS/JavaScript, WebGL 렌더러, GitHub Pages 배포 설정과 문서 초안을 작성했다.
- **UI 수정 방향:** 발표자가 시작 팝업, 전체 화면 그리기, 일시정지, 감상을 묻는 결과 화면, 오른쪽에서 펼치는 설정 메뉴라는 흐름을 제안했다. AI가 이 방향에 맞춰 화면과 기록 상태 관리를 수정했다.
- **비교 화면:** 발표자가 의도와 AI 해석의 차이를 보고 싶다고 제안했다. API 키가 없어 우선 결과 화면에 의도 입력과 고정된 해석 예시를 구현했으며, 실제 분석으로 오해하지 않도록 예시 표시와 AI 미연결 상태를 넣었다.
- **초기 버전 검증:** AI가 브라우저에서 직접 입력, 분리된 획 기록, 수동 종료, 재생, 단색 비교, 감상 선택, PNG 저장과 지우기를 확인했다. 공개 배포 후에는 페이지 접속, WebGL 화면 표시, 브라우저 오류 로그를 확인했다.
- **수정 UI 검증:** 시작 팝업, 직접 기록, 일시정지 시 시간 유지, 설정 메뉴를 열 때 자동 일시정지, 이어 그리기, 10초 자동 종료, 2개의 획 보존, 결과 화면 전환과 감상 선택을 확인했다.
- **비교 화면 검증:** 의도 선택·해제, 자유 입력, 빈 입력, 예시 열기·닫기, 같은 단어와 다른 단어의 안내, 새 예시를 불러올 때 입력 초기화, 기존 궤적 재생을 브라우저에서 확인했다. 콘솔 오류는 없었다.
- **결과 팝업 검증:** 어두운 결과 팝업, 닫기·다시 열기 시 입력 유지, `Esc`로 닫기와 재생 일시정지, 팝업에서 새 기록 시작, 직접 그린 궤적의 결과 팝업 전환을 확인했다. 흰 배경을 제거하고 입력창과 비교 카드도 어두운 색으로 통일했다.
- **검증 한계:** 위 확인은 기능 동작 점검이다. 발표자 자신의 코드 이해도, 관객 경험, 작품 질문의 타당성이 검증되었다는 의미는 아니다. 실제 관객 피드백과 해석은 이후 단계에서 추가한다.

## 실패와 배운 점

### 초기 화면에 궤적이 보이지 않는 문제

첫 브라우저 미리보기에서 예시 데이터가 있어도 무대가 비어 보이는 문제가 있었다. 캔버스 크기 조정과 예시 데이터 로딩 직후에도 렌더링하도록 수정했고, 이후 첫 화면에 궤적이 표시되는 것을 확인했다. 데이터 준비와 화면에 그리는 시점을 함께 관리해야 한다는 점을 확인했다.

### 작은 화면에서 기록 버튼과 무대가 떨어지는 문제

초기 UI에서는 좁은 화면의 조작 패널이 무대 아래로 내려가 기록 버튼을 누른 뒤 다시 위로 스크롤해야 했다. 처음에는 무대로 이동하도록 수정했고, 이후 피드백에 따라 전체 화면을 무대로 바꾸고 조작 버튼을 하단에 고정했다. 색과 굵기 설정은 오른쪽 메뉴로 옮기고, 감상 선택은 기록 후의 결과 화면으로 분리했다. 기능을 한꺼번에 보여주기보다 체험 순서에 맞게 보여주는 것이 중요했다.

### 움직임을 단순화하면서 잃는 정보

마우스의 좌표와 시간만으로는 몸의 무게, 관절과 신체 전체의 움직임을 담을 수 없다. 이 한계는 아직 해결하지 않았으며, 현재 프로토타입의 핵심 피드백 질문으로 남겼다. 속도와 색의 대응 역시 디자인 선택이지, 특정 감정의 객관적 판정이 아니다.

## 현재 한계와 다음 계획

- **예시 먼저 보기**는 합성 예시이며 실제 사용자 기록과 구분해 표시한다.
- 마우스와 터치는 입력 조건이 다르다. 실제 모바일 장치 전반에 대한 검증은 아직 하지 않았다.
- 여러 기록을 저장하거나 관객의 답변을 모으는 기능은 구현하지 않았다.
- 의도와 AI 해석 비교는 화면 프로토타입이다. 실제 모델 연결, 궤적 분석, 의미 비교는 다음 단계다.
- 수업에서 동일한 움직임의 단색·속도별 색상 표현을 비교하고, 관객이 느낀 차이와 이유를 수집한다.
- 피드백을 바탕으로 비교 기록 저장, 음악과의 관계, 몸의 정보를 추가할 필요성을 검토한다.

- [캡션카드.md](./캡션카드.md): 피그잼에 옮길 작품명, 이름, 질문, 체험 안내

발표 자료는 과제에서 허용한 **작업물 화면 링크** 형식으로 제출한다. 별도의 슬라이드 PDF는 포함하지 않는다.

## 제출 ZIP 구성과 오프라인 실행

```text
README.md
발표자료.md
캡션카드.md
dist/
  index.html
  styles.css
  app.js
```

압축을 모두 푼 뒤 `dist/index.html`을 Chrome 또는 Edge로 열면 된다. 설치, 빌드, API 키가 필요하지 않다. `.git`, 배포 설정, 개발용 서버, 미리보기 이미지 등은 제출 ZIP에서 제외했다.

## GitHub Pages 배포

공개 사이트: **https://yebe9.github.io/jansang/**

공개 저장소: **https://github.com/yebe9/jansang**

저장소에서는 `main`에 push하면 GitHub Actions가 JavaScript 문법을 확인하고 `dist`를 Pages에 배포한다. `.github/workflows/pages.yml`과 개발 서버 `server.cjs`는 저장소에서만 제공한다. 저장소를 내려받은 개발 환경에서는 `node server.cjs` 실행 후 `http://127.0.0.1:4173`에서도 확인할 수 있다.
