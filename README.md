## 질문 한 문장

> 내가 움직임에 담은 느낌과, 움직임을 본 AI가 읽은 인상은 얼마나 비슷하고 어디서 달라질까?

## 현재 흐름

1. **손끝으로 그리기 / 몸으로 남기기**를 고르고 카메라를 준비한다. 손은 최대 양손의 42개 지점, 전신은 얼굴을 제외한 22개 지점을 사용한다.
2. 최대 10초 동안 움직인다. 추적이 끊기거나 일시정지하면 그 사이를 새 동작으로 연결하지 않는다.
3. 기록이 끝나면 자동으로 AI 해석을 요청한다. 결과에서는 **내가 의도한 느낌**과 **나만의 말로 덧붙이기**를 나란히 적는다. 짧은 입력은 5글자까지이며 긴 입력의 원문은 자유 입력 칸에 보존한다. 여섯 느낌은 선택 버튼 대신 입력 예시다.
4. 움직임만 보고 AI가 선정한 **해석 결과 TOP 5**를 원래 순서로 보여주고, 각 표현과 내가 쓴 말의 의미 유사도를 막대로 표시한다. 내 의도를 바꿔도 AI 후보·순위·대표 인상은 바뀌지 않고 유사도만 다시 계산한다. 계산하지 못한 표현에는 임의의 점수를 붙이지 않는다.
5. 영상과 결과는 이 기기의 IndexedDB에 먼저 자동 보관한다. 시작할 때 열린 개인 기록함에 로그인하면 온라인 비공개 저장소로 동기화한다. 나중에 고친 의도·해석·유사도도 같은 기록에 갱신한다. 기기에는 즉시 보관하고 온라인 전송은 약 8초 간격으로 묶어 보낸다.

카메라를 준비하는 동안 기록함 탭이 열릴 수 있다. 미로그인·팝업 차단·네트워크 지연 시 화면의 보관 상태를 확인한다. **기기 보관과 온라인 저장 완료는 다르다.** 브라우저 데이터 삭제나 저장 공간 회수로 기기 대기 기록이 사라질 수 있다.

## 공개 페이지와 로컬 실행의 차이

| 환경 | 움직임 해석 경로 |
| --- | --- |
| 로컬 전신 + 3D 좌표 + MotionGPT 설정 | MediaPipe world 좌표 → HumanML3D 근사 변환 → **실제 MotionGPT CPU motion-to-text** → Gemini의 한국어 표현·감상 |
| 손 입력, 공개 GitHub Pages, MotionGPT 설정 없는 로컬 | 관측 좌표·움직임 수치 → Gemini의 한국어 표현·감상 |

공개 Cloudflare Worker에서는 PyTorch MotionGPT를 실행하지 않는다. 공개 주소를 연 것만으로 로컬 MotionGPT가 연결되는 것도 아니다. MotionGPT를 설정한 로컬 전신 경로에서 모델이나 3D 입력이 부족하면 오류를 표시하며, 다른 모델의 설명을 MotionGPT 결과로 표시하지 않는다.

로컬 MotionGPT는 GPU 없이 실행하도록 구성했다. 모델 파일만 약 **2.33GB**이며 Python 환경과 메모리도 필요하다. 로컬 전신 요청은 CPU 처리를 위해 최대 **180초**까지 기다리도록 구성했다. 느린 환경에서는 120–180초 대기도 가능하며 첫 모델 로딩은 더 오래 걸릴 수 있다. 이 대기 한도는 일반적인 응답 시간이나 성공 보장이 아니다. 2초·41개 시점의 합성 3D 자료를 모델 로딩 후 한 번 시험했을 때 CPU 추론 1.187초, HTTP 왕복 1.218초에 실제 설명을 받았다. 첫 로딩 시간은 측정하지 않았으며 이 단건 시험으로 실제 춤의 품질이나 응답 시간을 보장하지 않는다. 설치·모델 로딩·실제 추론 성공은 각각 확인하고 예전 Gemini 측정 시간을 현재 성능으로 소개하지 않는다. [설치와 연결](./AI연결안내.md)

## 추적과 해석의 범위

- MediaPipe Pose Landmarker Full / Hand Landmarker를 CPU 기본으로 실행한다. 선택한 GPU 실행에 실패하면 CPU로 복구한다. 속도 적응형 One Euro 필터는 작은 흔들림을 줄이고 빠른 동작의 지연을 줄이도록 조정했다. 실제 춤의 정확도가 향상됐다는 벤치마크를 마친 것은 아니다.
- 전신의 3D world 좌표는 MediaPipe가 추정한 골반 중심의 미터 단위 값이다. 화면 좌표를 3D처럼 바꿔 쓰지 않는다. 얼굴 좌표 0–10번은 필터·표시·기록·전송 전에 버린다.
- MotionGPT에는 별도의 입력 변환이 필요하다. 어깨·골반 등의 몸 좌표에서 척추·목·머리·루트 일부를 **근사 구성**하며 그 출처를 남긴다. 얼굴을 측정해서 머리 좌표를 얻는 것은 아니다. 골반 중심 좌표만으로 전역 이동 경로를 복원할 수 없다.
- MotionGPT는 [공식 motion-to-text 구현](https://github.com/OpenMotionLab/MotionGPT)을 선택했다. 문서에 제안된 [T2M-GPT](https://github.com/mael-zys/t2m-gpt)의 공식 구현은 text-to-motion 모델이므로 이 역방향 작업에 연결하지 않았다.
- Gemini는 제공된 [춤 표현 50선](./dance_descriptions.txt)과 움직임 근거로 인상을 표현한다. 유연함·유려함·역동성의 경험적 선택 기준을 적용하며, 사람의 감정이나 신체 능력을 판정하지 않는다.

## 좌표 해석 검증 · 2026-10-30

이전 화면은 AI의 다섯 후보를 받은 뒤 의미 유사도 내림차순으로 다시 정렬했다. 이제 화면과 기록함 모두 AI의 원래 순서를 보존한다. 유사도는 label로 결합하며 OOV는 측정불가로 남겨 다섯 행을 유지한다. 의도 변경 시 AI 호출이 늘어나지 않는 회귀 테스트를 추가했다.

해석 서버는 압축 전 모든 수신 좌표에서 관절별 실제 이동 폭(P90−P10), 속도 분포, 지속 시간, 빠른 구간 비율과 이동을 동반한 방향 전환을 직접 계산한다. 가장 빠른 부위의 클라이언트 평균 속도와 정적인 신체 폭은 Gemini 해석 입력에서 제외했다. 상체·하체·몸통의 근거를 분리하며 관절 누락·손 ID 변경·정지 구간을 잇지 않는다.

역동적인은 기본값이 아니다. 전신은 서로 다른 관절 최소 2개에서 각각 1.5초 이상·기록의 40% 이상 이어지고, 충분한 이동 폭·빠른 구간 20% 이상·움직임 구간 35% 이상·속도 또는 방향 변화가 함께 관측돼야 후보가 된다. 측정 가능한 몸통 길이가 있으면 이동 폭과 빠른 속도 기준은 각각 몸통 길이의 0.6배·초당 0.6배이며 화면 대각선 기준 0.04·초당 0.05의 잡음 방지 하한을 둔다. 몸통을 측정하지 못하면 화면 대각선 0.12·초당 0.12를 쓴다. 경험적 제한으로, 춤·감정의 검증된 분류기가 아니다. 카메라 거리·몸 숙임·투영의 영향을 완전히 제거하지 못한다.

전신 전송은 최대 80개의 실제 관측으로 늘리되 100KiB 예산을 지킨다. 3D 관절이 많으면 프레임 수가 줄어든다. 화면·world 필수 14관절의 누락과 중단 경계를 전송 전에 보존하고, Gemini에는 최대 24개 관측과 전체 수신 좌표의 파생 근거를 함께 보낸다. 이미 샘플링으로 사라진 빠른 동작은 복원할 수 없다.

실제 MotionGPT도 합성 팔 동작을 걷기·점프로 잘못 설명한 사례가 있었다. 캡션은 좌표보다 우선하는 사실이 아닌 보조 근거로 바꾸고, 추정 관절·루트 이동 손실 정보를 Gemini에 전달한다. 캡션만으로 걷기·점프·회전을 확정하지 않는다.

정지·작은 떨림·느린 큰 곡선·빠른 큰 동작·작은 스텝·느린 수평 이동의 합성 회귀 테스트와 실제 Gemini 요청을 사용했다. 합성 결과는 실제 사람의 춤 정확도를 뜻하지 않는다. node scripts/evaluate-motion.mjs <API주소> <결과JSON경로>로 재현할 수 있으며 API 호출이 발생한다. API 키는 서버에만 둔다.

## 유사도는 무엇을 뜻하나

[semantle-ko](https://github.com/NewsJelly/semantle-ko)의 **fastText 단어 벡터 + 코사인 유사도** 방식을 참고해 독립 구현했다. 상류의 GPL 코드를 복사한 것은 아니다. 실제 한국어 fastText에서 추출한 **50,112개 단어·300차원**의 int8 벡터를 약 **15MB**로 포함한다. 사전 출처·해시·변형 내용과 CC BY-SA 3.0 표시는 [third_party/semantle-ko](./third_party/semantle-ko/README.md)에 있다.

표시 값은 **코사인 유사도 × 100**, 범위는 **-100~100**이다. 감정의 확률이나 동작 일치율이 아니며 AI가 보고한 적합도와도 다르다. 문장은 알려진 단어 벡터를 평균하므로 **어순·부정·동음이의어·문맥**에 한계가 있다. 미등록어·모델 로딩 실패는 측정 불가로 남긴다.

유사도 계산은 브라우저 CPU에서 처리한다. 내 의도와 자유 입력을 Gemini나 MotionGPT에 보내지 않는다. 다만 개인 기록함에 로그인한 뒤에는 의도와 유사도 결과도 비공개 로그에 함께 저장된다.

## 기록과 개인정보

시작한 움직임의 원본 카메라 영상을 **소리 없이 자동 녹화**한다. 영상에는 얼굴과 주변 공간이 포함될 수 있으며 얼굴 좌표를 버리는 것과 영상에서 얼굴을 가리는 것은 다르다. AI 해석 서비스에는 원본 영상·음성·내 의도를 보내지 않는다.

기기 대기 기록은 IndexedDB, 온라인 영상은 Cloudflare KV, 의도·분석·유사도·버전과 세션은 D1에 둔다. 온라인 저장·목록·영상 조회에는 소유자 로그인이 필요하다. 후속 입력은 revision을 늘린 메타데이터 PUT으로 갱신하며 기존 영상은 다시 올리지 않는다. 이전 버전이 늦게 도착해도 최신 버전을 덮어쓰지 않는다. [비공개 로그 안내](./logbook/README.md)

Set-Location -LiteralPath 'C:\Projects_AI\Codex\라운지서울_잔상'

수동 실행은 Python MotionGPT 서비스와 Node 서버를 각각 실행한다. Node는 `.env`를 읽도록 `node --env-file=.env server.cjs`로 시작하고 [로컬 페이지](http://127.0.0.1:4173/)를 연다. 브라우저에서 Python 8765 포트에 직접 요청하는 방식이 아니다. API 키·비밀번호·가중치는 공개 Git이나 제출 ZIP에 넣지 않는다.

## AI USE NOTE · 과정과 배운 점

발표자가 전기정보공학·춤·그래픽이라는 질문, 어두운 무대와 잔상 표현, 춤 표현 50선과 개발 방향을 정했다. AI는 코드·변환·문서 초안과 테스트를 작성했다. 모델과 라이선스의 실제 조건을 확인하면서 공식 motion-to-text 경로와 한국어 벡터 비교를 분리했다.

추적을 놓친 앞뒤 좌표를 연결하면 하지 않은 동작이 생겼다. 손별 ID와 기록 구간을 나눠 대응했다. 익숙한 표현의 반복을 단순히 랜덤 선택으로 해결하지 않고, 관측 기준과 실제 모델 출력을 기록해 검토한다. 이전의 수동 저장은 자동 저장으로 오해하기 쉬웠으므로 기기 보관·로그인 대기·온라인 저장 상태를 분명히 나눴다.

남은 과제는 실제 춤의 빠른 회전·가림에서 추적이 유지되는지, MediaPipe에서 MotionGPT로 옮기는 근사가 표현에 어떤 영향을 주는지, 한국어 단어 유사도가 관객의 해석과 얼마나 다른지 확인하는 것이다. 완성된 감정 인식기로 소개하지 않는다.
