# 잔상 — 움직임을 남기는 방법

전유빈 · WebGL 기반 인터랙티브 웹 · WIP 프로토타입

[작업물 체험](https://yebe9.github.io/jansang/) · [GitHub 소스 코드](https://github.com/yebe9/jansang)

## 질문 한 문장

> 내가 움직임에 담은 느낌과, 몸의 외형 대신 궤적과 속도를 읽은 AI의 해석은 어떻게 다를까?

## 현재 상태

마우스·터치 또는 웹캠으로 최대 10초의 움직임을 남기고, 큰 결과 팝업에서 내 의도와 움직임의 특징을 나란히 볼 수 있다. 웹캠에서는 MediaPipe가 브라우저 안에서 자세를 인식하고, 양 손목의 자취를 WebGL로 그린다.

**기본 수치 분석**은 API 키 없이 실행된다. 속도·멈춤·범위·방향 전환을 계산해 규칙으로 설명하며 생성형 AI 답변으로 표시하지 않는다. **실제 Gemini 해석**을 요청하고 표시하는 코드도 포함했지만, 현재 API 키가 제공되지 않았고 공개 AI 서버도 배포하지 않았다. 공개 Pages의 AI 버튼은 연결 안내를 표시하며 수치 분석 결과를 유지한다. 실제 Gemini 응답을 받아 검증한 상태는 아니다. 연결 방법은 [AI연결안내.md](./AI연결안내.md)에 있다.

## 질문과 조사

전기정보공학과 춤, 컴퓨터 그래픽에 대한 관심에서 시작했다. 처음 질문은 “몸의 모양 없이, 움직임의 궤적과 속도만으로 춤의 느낌을 전달할 수 있을까?”였다. 마우스 궤적을 만든 뒤 내 의도와 다른 해석을 비교하는 방향으로 확장했고, 몸의 움직임을 직접 입력하기 위해 웹캠을 추가했다.

기술 조사에서는 브라우저용 자세 인식과 무료 사용 범위가 있는 생성형 API를 확인했다.

- **MediaPipe Pose Landmarker:** 영상 프레임의 자세 랜드마크를 얻는 공식 웹 API를 참고했다. Lite 모델과 `@mediapipe/tasks-vision`을 사용하며, 손목·어깨를 기준으로 기록한다. 추론이 메인 스레드를 막을 수 있어 호출을 최대 초당 15회로 제한했다. [공식 웹 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)
- **Gemini API:** 기본 모델은 `gemini-2.5-flash`다. 공식 요금표에 무료 입력·출력 구간이 있으나 사용량 제한이 있으며, 무료 구간의 입력·출력은 Google의 제품 개선에 사용될 수 있다. [Gemini 요금표](https://ai.google.dev/gemini-api/docs/pricing)
- **API 키 보관:** 공개 웹 코드에 키를 넣지 않고 서버가 Gemini를 호출하게 했다. 로컬 Node 서버와 Cloudflare Worker용 코드를 함께 준비했다. [Gemini API 키 안내](https://ai.google.dev/gemini-api/docs/api-key)

이는 기술 문서 조사와 구현을 통한 탐색이다. 관객 대상 실험, 감정 분류 정확도 평가, 실제 무용 동작과 마우스 입력의 비교 연구는 아직 진행하지 않았다.

## MVP 체험 방법

WebGL을 지원하는 Chrome 또는 Edge에서 [공개 체험 페이지](https://yebe9.github.io/jansang/)를 연다.

1. 시작 팝업에서 **손으로 그리기** 또는 **몸으로 남기기**를 선택한다.
2. 손으로 그리기는 무대를 처음 누르는 순간부터 기록한다. 누른 채 움직이고, 손을 떼었다가 다시 누르면 새 획이 된다.
3. 몸으로 남기기는 카메라 권한을 허용하고 모델을 기다린다. 미리보기에서 어깨와 양손이 보이도록 선 뒤 **10초 기록 시작**을 누른다. 양 손목의 움직임이 각각 잔상이 된다.
4. **일시정지**로 시간을 멈추거나 오른쪽 **색·굵기** 메뉴를 연다. 설정 메뉴를 열면 기록도 멈춘다. 이어서 기록하는 버튼으로 재개하며, 웹캠은 몸이 다시 인식될 때 기록한다.
5. **결과 보기** 또는 10초 자동 종료로 어두운 큰 결과 팝업을 연다. 내 의도를 단어로 고르거나 직접 적고, 기본 수치 분석의 인상과 근거를 비교한다.
6. AI 서버를 연결했다면 **AI로 움직임 해석하기**를 누른다. 시작 팝업의 **기록 후 AI로 인상 해석하기**를 선택해 두면 기록 후 자동 요청한다. 성공한 응답에만 **Gemini 해석** 표시가 붙는다.
7. 재생, 구간 탐색, 0.5/1/1.5배속, 속도별 색과 단색 비교를 해본다. **잔상 이미지 저장**으로 궤적 PNG를 저장할 수 있다.

카메라 권한이 없거나 모델을 불러오지 못하면 손으로 그리기로 체험할 수 있다. **예시 먼저 보기**는 사람이 만든 기록이 아닌 합성 궤적이며 결과에 구분해 표시한다.

결과 팝업의 **잔상 크게 보기** 또는 `Esc`로 전체 무대를 볼 수 있고, **의도와 해석 다시 보기**로 돌아와도 현재 기록과 입력은 유지된다. 시작·기록·결과 화면은 모두 어두운 배경이다. 시작 팝업의 흰 곡선에는 빛의 자취가 흐르며, 동작 줄이기 설정에서는 장식 애니메이션을 멈춘다.

## 기록과 분석의 범위

웹캠 영상은 브라우저의 자세 인식 입력으로만 사용한다. 소리를 수집하지 않고 원본 영상을 녹화·저장·전송하지 않는다. MediaPipe 라이브러리와 모델을 내려받으므로 웹캠 기능에는 인터넷 연결이 필요하다. 카메라는 HTTPS 또는 로컬 서버에서 사용한다.

브라우저 메모리에는 궤적, 최대 8개 상체 관절의 2D 좌표, 시간과 기록 구간을 남긴다. 어깨·손목을 인식하지 못한 동안과 사용자가 일시정지한 시간은 기록에서 제외하며, 재개 시 이전 구간과 연결선을 만들지 않는다. 새 기록이나 새로고침으로 이전 내용이 사라진다. 결과로 이동하면 카메라를 종료한다.

AI 해석을 선택할 때만 최대 60개 시점의 좌표와 요약 수치를 서버를 거쳐 Google Gemini로 보낸다. **얼굴, 원본 영상, 음성, 내가 적은 의도는 보내지 않는다.** 서버 코드에는 움직임을 파일이나 데이터베이스에 저장하는 기능이 없다. 외부 API의 데이터 처리에는 제공자의 조건이 적용된다.

AI가 받는 자료는 원본 영상이 아니라 좌표와 수치다. 답변은 “경쾌한 리듬처럼 읽힐 수 있다”와 같은 표현의 인상을 설명한다. 실제 감정, 성격, 건강이나 숨은 의도를 판정하는 도구가 아니다. 의도와 해석의 정확도·일치율도 계산하지 않는다.

## 핵심 구조

```text
마우스·터치 ── 좌표·시간·획 번호 ───────┐
                                        ├─ WebGL 잔상 → 기록 재생
웹캠 → MediaPipe → 양 손목 궤적 ───────┘
                  └─ 최대 8개 관절 좌표
                            ↓
        속도·멈춤·공간 사용·방향 전환 계산
                            ↓
        기본 수치 분석 → 결과 팝업에 즉시 표시
                            ↓ AI 해석을 선택한 경우
        좌표 샘플 + 수치 → 비공개 키를 가진 서버
                            ↓
             Gemini → 인상·설명·근거 표시
                            ↓
             내가 입력한 의도와 나란히 보기
```

- `dist/index.html`, `dist/styles.css`: 시작·기록·결과 팝업과 반응형 디자인.
- `dist/app.js`: 입력 방식, 기록 상태, WebGL 선분, 재생, 비교 화면, AI 요청.
- `dist/pose-camera.js`: 카메라 권한, MediaPipe 모델 로딩, 자세 추적, 미리보기, 카메라 해제.
- `dist/motion-analysis.js`: 좌표 정리, 수치 계산, 최대 60개 시점 샘플링과 기본 설명.
- `dist/config.js`: 공개 AI 서버 주소만 설정한다. API 키를 넣는 파일이 아니다.
- `server.cjs`, `api/handler.mjs`: 로컬 서버와 공통 Gemini 프록시.
- `api/worker.mjs`, `wrangler.toml`: 공개 AI 서버를 위한 Cloudflare Worker.

그리기는 외부 그래픽 라이브러리 없이 WebGL 1.0으로 구현했다. 선분을 삼각형으로 바꾸고 넓고 흐린 선과 좁고 밝은 선을 합성한다. 속도별 색은 화면 높이 기준 속도를 사용한다. 분석 수치는 화면 대각선을 1로 둔 거리·속도를 사용하므로 색 표현의 내부 값과 단위가 다르다. 결과에서는 기록 당시 화면 비율을 보존한다.

수치 분석은 연속 관측만 연결한다. 새 획, 새 기록 구간, 누락된 관절, 250ms보다 긴 관측 공백을 건너뛰어 임의의 속도를 만들지 않는다. 손목 두 개의 속도를 평균해 손이 두 개라는 이유로 속도가 두 배가 되지 않게 했다. 최소 1초, 유효 관측 8개, 연속 관측 합계 500ms를 충족해야 AI 요청 버튼을 활성화한다.

## AI 활용 과정 · AI USE NOTE

- 발표자가 전기정보공학·춤·OpenGL·산책에 대한 관심을 제시했고, AI와 주제를 좁혀 WebGL로 움직임의 잔상을 만들기로 했다.
- AI가 HTML/CSS/JavaScript, WebGL 렌더러, 배포 설정, 문서 초안을 작성했다. 발표자는 시작 팝업, 전체 화면 무대, 일시정지, 오른쪽 설정 메뉴, 큰 어두운 결과 팝업 등 체험 흐름과 디자인 방향을 정하고 수정을 요청했다.
- 처음에는 API 키가 없어 의도와 고정 예시를 비교하는 화면만 만들었다. 이후 요청에 따라 고정 해석을 현재 움직임의 **수치 분석**으로 바꾸고, 실제 Gemini 호출 경로와 연결 안내를 추가했다.
- 웹캠 입력에는 무료 오픈소스 자세 인식 라이브러리를 적용했다. AI와 함께 원본 영상 대신 좌표를 사용하는 범위를 정하고, 영상 추적과 생성형 해석을 분리했다.
- 좌표 분석 테스트로 정지/빠른 움직임, 누락 관절, 일시정지 후 위치 이동, 여러 손목의 중복 계산, 샘플링 경계를 확인했다. 서버는 입력 검증, 키 미설정, 외부 API 실패 등의 처리를 자동 테스트한다.
- 자동 테스트는 시뮬레이션된 데이터와 응답을 포함한다. 실제 카메라 환경별 인식 품질, 실제 Gemini 응답의 적절성, 관객이 느끼는 차이는 별도 검증이 필요하다. 현재 Gemini 키가 없어 실제 API 호출은 검증하지 못했다.

## 실패와 배운 점

**데이터와 렌더링의 순서:** 초기에는 예시 좌표가 있어도 캔버스가 비어 보였다. 크기 조정과 데이터 로딩 직후에도 그리도록 수정했다. 데이터를 준비하는 시점과 화면에 그리는 시점을 함께 관리해야 했다.

**한 화면에 너무 많은 기능:** 작은 화면에서 무대와 조작 버튼이 멀어졌다. 시작·기록·결과로 나누고, 설정은 옆 메뉴에, 의도 비교는 결과 팝업에 배치했다. 기능의 수보다 경험의 순서가 중요했다.

**일시정지 뒤 생기는 가짜 움직임:** 멈춘 시간을 빼기만 하면 재개한 위치까지의 이동이 매우 빠른 동작처럼 계산될 수 있다. 획과 웹캠 기록 구간을 나누고 서로 다른 구간을 연결하지 않도록 했다.

**좌표만으로 잃는 정보:** 웹캠을 추가해도 현재 잔상은 손목 중심이다. 무게중심, 몸의 회전, 깊이, 표정, 음악과의 관계를 충분히 담지 못한다. 2D 좌표와 임의의 임계값으로 얻은 특징을 감정의 정답으로 해석하면 안 된다는 한계가 남는다.

## 현재 한계와 다음 계획

- 한 사람을 대상으로 하며 가림, 어두운 환경, 빠른 움직임, 카메라 바깥 관절에서 추적이 흔들릴 수 있다. 실제 모바일 장치와 다양한 카메라에 대한 검증은 아직 필요하다.
- 자세 추론은 최대 15fps로 제한했지만 메인 스레드에서 실행하므로 느린 기기에서 끊길 수 있다. 다음에는 Web Worker와 추적 품질 표시를 검토한다.
- 수치 분석의 표현은 정해 둔 규칙이며 검증된 감정 모델이 아니다. Gemini도 줄어든 관측 자료로 인상을 생성하므로 근거가 부족하거나 부정확한 설명이 나올 수 있다.
- 현재 의도는 움직임을 만든 **후에** 입력한다. 다음 실험에서는 의도를 먼저 기록하고, 관객에게는 의도를 숨긴 채 감상을 받은 뒤 비교하려 한다.
- 관객 피드백, 여러 기록 저장, AI 해석 비교 기록의 수집은 아직 구현하지 않았다.
- API 키와 공개 서버를 연결한 뒤 실제 생성 응답을 점검한다. 무료 할당량이 끝나거나 API가 실패해도 기본 수치 분석과 잔상 체험은 유지한다.

## 받고 싶은 피드백

- 내 의도를 듣기 전에 궤적에서 어떤 느낌이 읽혔고, 어떤 속도·멈춤·방향이 그렇게 느끼게 했나요?
- 손목 자취만으로 춤의 리듬이 전달되나요? 추가로 필요한 몸의 정보는 무엇인가요?
- 수치 설명과 AI의 감상 중 무엇이 도움이 되나요? 다른 해석을 받아들이려면 어떤 근거가 필요할까요?

## 제출물과 실행

[발표자료.md](./발표자료.md)는 작업물 화면 링크를 사용하는 3분 발표 순서이고, [캡션카드.md](./캡션카드.md)는 피그잼에 옮길 내용이다. 발표용 별도 PDF는 포함하지 않는다.

제출 ZIP에는 다음 파일을 넣는다.

```text
README.md
발표자료.md
캡션카드.md
AI연결안내.md
.env.example
server.cjs
wrangler.toml
api/
  handler.mjs
  worker.mjs
dist/
  index.html
  styles.css
  app.js
  pose-camera.js
  motion-analysis.js
  config.js
```

ZIP을 모두 풀고 `dist/index.html`을 열면 **마우스·터치 기록, 합성 예시, 재생, 기본 수치 분석**을 오프라인으로 체험할 수 있다. 웹캠은 모델 다운로드를 위한 인터넷과 HTTPS 또는 로컬 서버가 필요하다. Node.js 20.6 이상에서 압축을 푼 폴더의 터미널로 `node server.cjs`를 실행한 뒤 `http://127.0.0.1:4173`에 접속하면 된다. 키 없이 실행해도 웹캠과 수치 분석은 사용할 수 있다.

실제 AI 연결은 [AI연결안내.md](./AI연결안내.md)를 따른다. `.env.example`은 빈 키 설정 예시다. **실제 키가 들어 있는 `.env`, 비밀 설정, `.git`, 개발 캐시, 미리보기 이미지는 제출하거나 공개하지 않는다.** 소스 저장소에는 개발 테스트와 GitHub Actions 설정도 포함되며, `main`에 push하면 검사를 거쳐 `dist`를 Pages에 배포한다. Pages 배포만으로 Gemini 서버가 배포되지는 않는다.
